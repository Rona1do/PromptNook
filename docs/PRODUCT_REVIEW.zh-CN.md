# PromptNook 产品改进记录

评估日期：2026-10-05。以下判断来自当前代码、README、路线图与公开 GitHub 数据；产品效果仍需真实用户验证。

## 当前证据与判断

- GitHub API 显示仓库创建于 2026-08-27 UTC，截至本次评估有 4 Stars、1 Fork。最新 Windows 预览版 `v0.2.3-beta.1` 的安装包公开下载计数为 1，上一版为 0。[仓库数据](https://api.github.com/repos/Rona1do/PromptNook)、[发行数据](https://api.github.com/repos/Rona1do/PromptNook/releases)。下载计数会变化，也不代表独立用户或成功安装数。
- 没有访问来源、浏览器使用次数、留存或用户访谈数据，不能把少量 Star 直接归因为产品质量差，也不能断言是推广不足。桌面安装包的使用规模很小是可观察事实，曝光与转化各占多少仍未知。
- 当前卖点是保存 Prompt、模型与参数并导出工作流。[ComfyUI 本身已有工作流保存、加载及从生成媒体恢复工作流的能力](https://github.com/Comfy-Org/ComfyUI/blob/master/README.md#features)。因此，用户需要清楚看到 PromptNook 在跨出图整理、检索、去重、比较和复用上能节省哪些操作。
- 导入能识别 diffusion-model 图，但当前导出只生成 checkpoint 文生图模板。FLUX 用户会在复用阶段遇到明显断点，复杂自定义节点也不会被完整重建。
- 桌面版只有未签名 Windows beta；浏览器版已经可以无需安装试用。推广应优先让用户用自己的出图完成一次有价值的操作，再介绍桌面版的扫描与备份能力。
- 界面为英文，简体中文仅有文档。中文界面可以降低中文用户的试用门槛，但应完整实施本地化，避免只有首页翻译而保存错误仍无法理解。

## 本次已实现：批量出图入库预览与去重

场景：把多张 ComfyUI 出图、工作流 JSON 或 A1111 参数文件一起导入，筛选后整理成配方库。

1. 先展示每个文件的模型、LoRA 数量、尺寸和步数；展开查看 Prompt、采样器、CFG、种子、LoRA 顺序与强度、导入说明和 PNG 封面。
2. 对比当前工作区和本批次中的已解析条目，默认不勾选生成信息相同的重复项；用户仍可主动保留另一份。
3. 不同种子、Prompt、负面词、模型、LoRA 顺序或强度、尺寸与采样参数分别保留。
4. 逐项显示解析或保存错误；其余有效文件可正常入库。重试只处理仍选中且尚未保存的条目。
5. 用户选定保存后才导入封面资产；取消预览不会写入配方或媒体。隐私模式下不展示 Prompt 与封面。

去重比较的是提取后的配方字段，不是完整源工作流。封面、标题和普通备注不参与比较，可能具有不同自定义节点的两张图也可能提取出相同字段；这类情况可以手动勾选重复项。本次没有实现旧配方合并或全库清理。

验证：83 项前端测试通过，生产构建通过；5 项浏览器端到端测试通过，1 项可选文档截图任务跳过。新增浏览器场景覆盖真实 PNG 元数据与封面、混合文件、默认去重、保存后刷新及再次导入。桌面原生安装、文件系统和跨机器恢复没有在本次重新验证。

## 后续优先级

| 优先级 | 改进 | 用户价值与完成条件 |
| --- | --- | --- |
| P1 | 保存并导出原始 ComfyUI 图 | 保留自定义节点和 FLUX 图；提供明确的“导出原图”入口，与“根据编辑后配方生成图”区分。需覆盖数据库迁移、浏览器备份、桌面备份和往返测试。原图导出不能冒充已同步配方修改。 |
| P1 | FLUX 专用配方导出 | 根据已保存的配方修改 Prompt 和参数后，仍能生成可编辑图。应明确支持的模型变体，保存文本编码器和 VAE 选择，验证标准节点连接与真实加载。不能仅把 checkpoint loader 替换成 UNET loader。 |
| P1 | 配方与出图对比 | 并排查看两个结果，突出 Prompt、LoRA、种子和采样参数差异，帮助用户筛选最佳结果并保留迭代过程。 |
| P2 | 完整简体中文界面 | 自动检测与手动切换，覆盖导入、导出、设置、备份、错误提示；补齐 locale 完整性检查。 |
| P2 | 可移植单配方分享包 | 让别人导入封面、参数和所需资源清单，不携带模型权重、凭据或机器路径；从库内备份扩展到单配方分享。 |

## 下一次更新如何验证价值

- 用真实示例录制一段短演示：拖入一批出图 → 查看参数 → 跳过重复 → 保存 → 搜索找到结果 → 导出 checkpoint 图。明确标注 FLUX 当前的导出限制。
- 以“整理你已有的 ComfyUI 出图”为首个使用场景，浏览器体验链接放在主要入口。安装版作为需要本地目录扫描时的后续选择。
- 邀请少量真实 ComfyUI 用户用自己的文件试用，记录是否完成导入、在哪一步退出、哪些图无法识别、下次是否仍愿意使用。公开宣传、联系用户和发布新版本需由维护者执行或另行授权。
- 结合维护者能访问的 GitHub Traffic、Release 下载变化和上述反馈决定后续开发。没有使用证据前，不把 Star 数作为唯一成功指标，也不添加默认上传 Prompt 或工作流的遥测。
