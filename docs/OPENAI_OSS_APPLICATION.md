# OpenAI open-source maintainer application draft

Official form: <https://openai.com/form/codex-for-oss/>

## Eligibility reality check

The program describes support for active maintainers of open-source projects. Selection is not automatic. The published criteria emphasize project usage/adoption, ecosystem importance, and maintenance activity. A newly created repository has little evidence on those dimensions, so the strongest honest approach is to publish a useful release, maintain it consistently, earn real users and contributors, then apply with verifiable links.

Do not buy stars, invent download counts, exaggerate platform support, or describe private development history as public maintenance.

## Short project description

> PromptNook is an MIT-licensed, local-first desktop library and prompt studio for generative-image creators. It organizes reusable prompt fragments, model-specific workspaces, generation settings, local model/LoRA metadata, and verified backups without requiring a cloud account. Translation is optional, explicit, and compatible with local endpoints.

## Why the project matters

> Prompt workflows are often trapped in text files, proprietary cloud tools, or application-specific metadata. PromptNook gives creators a private and portable workflow, while its user-defined workspaces avoid hard-coding a particular model vendor. The project focuses on safe local storage, transparent network boundaries, and formats that users can export.

## How Codex Pro would help

> Six months of Codex Pro would help maintain PromptNook's Rust and TypeScript codebase, expand regression tests around backups and migrations, complete the localization architecture, review community pull requests, and verify cross-platform packaging. The benefit would be used for public maintenance work tracked through issues, pull requests, releases, and security fixes.

## Recommended application timing

Apply after at least one stable public release and a visible period of maintenance. A reasonable evidence target is several weeks of public commits, responsive issue handling, real release downloads or community references, and at least one external contribution or detailed user report. These are strategy targets, not official minimums.
